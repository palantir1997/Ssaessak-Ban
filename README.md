# 🌱 새싹병원 보안 관제 시스템 (Ssaessak-Ban)

> 의료기관을 대상으로 한 사이버 공격에 대응하기 위한 **웹 서비스 + 실시간 보안 관제 시스템** 구축 프로젝트

국내 의료기관을 대상으로 한 랜섬웨어 공격이 매년 증가하고 있지만, 보안 인력과 예산 부족으로 체계적인 대응이 어려운 현실에서 출발한 프로젝트입니다. 병원 웹사이트와 관리자 페이지를 직접 구축하고, 그 위에 IDS/IPS · SIEM 기반의 실시간 침입 탐지 및 시각화 체계를 더해 **공격받았을 때 무엇이 보이는지**를 직접 구현하고 검증했습니다.

[![공격부터 탐지까지 — 새싹병원 보안 인프라 구축](https://img.youtube.com/vi/VvKSCRkPEwg/maxresdefault.jpg)](https://www.youtube.com/watch?v=VvKSCRkPEwg)

- GoAccess, Zabbix를 통한 로그/리소스 모니터링 구축
- SIEM 보안관제센터 구축 (Graylog)
- KISA 기준 Shell Script 자동 점검 도구 작성
- Victim/Attacker 시나리오 기반 모의해킹 시연

## 🛡 보안 강화 조치

서비스에 의도적으로 취약점을 심어 탐지 가능 여부를 검증한 뒤, 아래와 같이 보강했습니다.

| 항목 | 강화 전 | 강화 후 |
|---|---|---|
| 패스워드 정책 | 제한 없음 | 8자 이상 + 특수문자 + 대소문자 혼합 |
| 로그인 실패 차단 | 없음 | 10회 이상 실패 시 계정 자동 잠금 |
| 세션 타임아웃 | 없음 | 30분 미사용 시 자동 로그아웃 |
| CAPTCHA | 없음 | 로그인 시 Google reCAPTCHA 적용 |
| SQL Injection | 탐지만 됨 | 탐지 즉시 자동 차단 |
| 네트워크 스캔 탐지 | 대응 없음 | Suricata로 Nmap 등 비인가 스캔 차단 |
| 비정상 로그인 시도 | 허용 | 10회 이상 시도 시 IP 차단 |

로그인 폼에 SQL Injection을 시도하면 즉시 차단되고, 관제 대시보드에 실시간으로 탐지 로그가 기록됩니다.

## 🔍 Red/Blue Team 모의해킹 및 관제 검증

[![7팀 새싹반 시연 영상](https://img.youtube.com/vi/7QbiI7gYo_M/maxresdefault.jpg)](https://www.youtube.com/watch?v=7QbiI7gYo_M)

Kali Linux에서 다양한 공격 시나리오(Nikto 스캔, 대량 트래픽, 디렉토리 스캔, 관리자 페이지 무단 접근, User-Agent 조작, Nmap 정찰, SSH Brute Force 등)를 직접 수행하고, 각 모니터링 도구가 이를 어떻게 탐지하는지 검증했습니다.

### Graylog — SIEM 기반 실시간 탐지
Nmap 정찰, SSH Brute Force, 권한 상승 시도 등을 임계치 기반 룰로 탐지합니다.


### 관제 대시보드 (Grafana 연동)
Suricata 탐지 로그를 Python 파서가 실시간으로 분류하여 MySQL에 저장하고, 관리자 페이지에서 공격 유형별 분포·위험도·실시간 위험 피드를 한눈에 확인할 수 있습니다.


### 그 외 검증 도구
- **GoAccess** — Nikto 스캔, ab 트래픽, dirb 디렉토리 스캔 등 웹 접근 로그 기반 이상 패턴 시각화
- **Suricata + Python 연동** — fast.log를 실시간 파싱하여 공격 유형·IP·위험도 자동 분류 후 DB 저장
- **Zabbix** — CPU/메모리 부하, Apache·MySQL 서비스 중단 등 인프라 이상 상태 실시간 모니터링

## 🔧 Shell Script 자동 점검 (KISA 기준)

Python으로 작성한 KISA 유닉스 취약점 점검 스크립트를 크론탭으로 매일 새벽 2시 자동 실행하며, 계정관리·파일/디렉토리 관리·서비스 관리·패치/로그 관리에 병원 서비스 특화 점검 항목(Apache root 실행 여부, MySQL root 패스워드 설정 등)을 추가해 총 31개 항목을 점검합니다.

![1차/2차 점검 결과](images/shell-script-result.jpg)

발견된 취약점(불필요한 SUID/SGID, FTP 평문 전송, DB root 계정 보안 미흡)을 즉시 조치한 뒤 재점검하여 **89점 → 100점**으로 개선했습니다.

## 📝 회고

**잘된 점**
- 웹 서비스 구축부터 보안 관제 시스템(Zabbix, Grafana, Graylog) 구축, 모의해킹까지 공격자/방어자 관점을 모두 경험
- 제한된 환경에서도 대체 방안을 활용해 문제를 해결하고 프로젝트를 완성

**아쉬운 점**
- 웹 구축과 관제 시스템 구축 일정이 분산되어 보안 관제 실습 착수가 다소 지연
- VM 용량/자원 부족으로 서버 분리 구성, Agent 설치 등에 제약
- SQL Injection·XSS·DDoS 등 다양한 공격 시나리오에 대한 탐지 규칙 실습 범위가 부족

**개선하고 싶은 점**
- 프로젝트 시작 전 실습 환경(PC 사양, VM 용량, 패키지 호환성) 사전 점검
- VPN 및 중앙 서버 기반의 통합 환경 구축으로 실무형 협업 구조 경험
- 모니터링·서비스·로그 저장 서버 분리로 안정적이고 확장 가능한 관제 환경 구축
- 다양한 공격 기법에 대한 탐지 규칙 추가 및 실습 범위 확대
